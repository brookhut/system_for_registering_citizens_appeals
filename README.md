# Система регистрации обращений граждан

Веб-приложение на Flask с базой данных PostgreSQL для учета, контроля сроков и обработки обращений граждан.

## Основные возможности

1. **Ролевая модель доступа**:
   - **`superadmin`**: Встроенный администратор. Логин и пароль хранятся в файле `.env`. Данная учетная запись **защищена от удаления, изменения и отключения**. При запуске приложения администратор авторизуется и наполняет справочники актуальной информацией организации, управляет пользователями-регистраторами и настраивает зависимости справочников.
   - **`registrator`**: Регистратор обращений (создается superadmin). Добавляет новые обращения со статусом «В работе», редактирует открытые обращения, отслеживает контрольные сроки и закрывает обращения.

2. **Главная страница**:
   - Вкладка **«В работе»** с актуальным счетчиком обращений.
   - Вкладка **«Закрытые обращения»** с актуальным счетчиком закрытых обращений.
   - **Поля поиска и фильтрации** над вкладками:
     - Номер обращения (поиск по фрагменту)
     - Дата регистрации (европейский формат ДД.ММ.ГГГГ, не позднее текущей даты)
     - Управление (выпадающий список)
     - Округ (выпадающий список)
     - Тип обращения (выпадающий список)
     - Тематика (выпадающий список)
     - Количество дней до ответа (просроченные, сегодня, 1-3 дня, до 7 дней, более 7 дней, без срока, точное число дней)
   - **Отображаемые столбцы**:
     - Номер обращения (с датой регистрации в европейском формате ДД.ММ.ГГГГ, без времени)
     - Округ
     - Управление
     - Тип обращения (с тематикой)
     - Состоит на обслуживании (Да / Нет)
     - Срок ответа в количестве дней (бейджи с цветовой индикацией: просрочено, сегодня, дней до окончания срока или закрыто)
   - Переход в карточку обращения по клику на любую строку таблицы.
   - Кнопка **«Добавить обращение»**.

3. **Форма добавления обращения** (начальный статус «В работе»):
   - **Дата регистрации**: европейский стандарт (ДД.ММ.ГГГГ), без времени, не может быть больше текущей даты, обязательное поле.
   - **№ обращения**: указывается из внешней системы, обязательное поле.
   - **Источник поступления**: справочник superadmin, обязательное поле.
   - **Округ**: справочник superadmin, обязательное поле.
   - **Управление**: справочник superadmin, опциональное поле.
   - **Участок**: справочник superadmin, опциональное поле.
   - **Пол заявителя**: выпадающий список (мужской, женский), опциональное поле.
   - **Тип обращения**: справочник superadmin, обязательное поле.
   - **Тематика обращения**: справочник superadmin, обязательное поле.
   - **Обоснованность**: выпадающий список (обоснован, не обоснован), опциональное поле.
   - **Повторность**: выпадающий список (Первичное, Повторное, Многократное), опциональное поле.
   - **Результат рассмотрения**: справочник superadmin, опциональное поле.
   - **Контрольные сроки**: дата поступления ответа в систему (европейский стандарт).
   - **Не состоит на обслуживании**: чекбокс (влияет на колонку «Состоит на обслуживании»).
   - **Комментарий**: текстовое поле, опциональное поле.

4. **Карточка обращения и закрытие**:
   - Фиксация автора записи и даты/времени создания (`created_by`, `created_at`).
   - Кнопка **«Закрыть обращение»**: после закрытия карточка блокируется для любого редактирования, статус меняется на **«Закрыто»**, фиксируется дата закрытия (`closed_at`) и ответственный (`closed_by`).

5. **Зависимости справочников**:
   - В одно **Управление** может входить несколько **Округов**.
   - В одно **Управление** может входить несколько **Участков**.
   - Администратор настраивает связи в разделе «Зависимости управлений» (`/admin/relations`).
   - На форме обращения реализована динамическая фильтрация связанных округов и участков при выборе управления.

## Учетная запись администратора (.env)

| Параметр | Значение по умолчанию | Описание |
|----------|-----------------------|----------|
| `SUPERADMIN_USERNAME` | `superadmin` | Логин встроенного администратора |
| `SUPERADMIN_PASSWORD` | `SuperAdminPass2026!` | Пароль встроенного администратора |

Учетная запись инициализируется автоматически при первом запуске приложения и защищена от удаления, отключения или изменения через интерфейс.

## Переменные окружения (.env)

По умолчанию проект настроен на работу через выделенного пользователя БД **`appeals_user`**:

```env
# База данных PostgreSQL (выделенный пользователь appeals_user)
DB_HOST=localhost
DB_PORT=5432
DB_NAME=appeals_db
DB_USER=appeals_user
DB_PASSWORD=appeals_pass_2026
DATABASE_URL=postgresql://appeals_user:appeals_pass_2026@localhost:5432/appeals_db

# Встроенный супер-администратор (защищен от изменений в UI)
SUPERADMIN_USERNAME=superadmin
SUPERADMIN_PASSWORD=SuperAdminPass2026!
SUPERADMIN_FULL_NAME=Главный администратор

# Конфигурация Flask
SECRET_KEY=citizens-appeals-secret-key-2026-secure-token
FLASK_ENV=production
PORT=5000
```

## Чистая установка и запуск на сервере (PostgreSQL 16)

### Создание пользователя БД в PostgreSQL:
Для создания выделенного пользователя `appeals_user` выполните на сервере:
```bash
sudo -u postgres psql -c "CREATE USER appeals_user WITH PASSWORD 'appeals_pass_2026' CREATEDB;"
```
*(Также в проекте доступен скрипт `./create_db_user.sh`, который попытается выполнить эту настройку автоматически).*

### Быстрый запуск в одну команду:

В проекте создан единый исполняемый скрипт **`start.sh`**, который автоматически выполняет весь цикл:
1. Проверяет наличие `.env` (при отсутствии копирует из `.env.example`).
2. Проверяет виртуальное окружение `venv` и зависимости (при отсутствии создает и устанавливает).
3. Проверяет и при необходимости запускает службу PostgreSQL.
4. Проверяет/создает пользователя БД `appeals_user`.
5. Пересоздает базу данных и таблицы с нуля (если БД уже существует — пересоздает структуру).
6. Проверяет свободный порт (если `5000` занят, автоматически находит и переключается на свободный).
7. Запускает приложение.

```bash
# Запуск полного цикла развертывания и старта:
./start.sh

# Запуск только веб-сервера без повторного пересоздания БД:
./start.sh --no-recreate
```

## Автоматический запуск при включении или перезагрузке сервера (systemd)

Для автоматического запуска приложения при загрузке или перезагрузке сервера подготовлен скрипт **`install_autostart.sh`**.

### Установка автозапуска:
Выполните в каталоге проекта:
```bash
./install_autostart.sh
# или с явным вызовом sudo:
sudo ./install_autostart.sh
```

**Что делает скрипт:**
1. Создает системную службу `/etc/systemd/system/appeals.service`.
2. Настраивает порядок запуска: приложение стартует только после того, как поднята сеть и служба PostgreSQL (`After=postgresql.service`).
3. Запускает проект от имени текущего пользователя в фоновом режиме с флагом `--no-recreate` (что гарантирует сохранность всех существующих данных в БД).
4. Настраивает автоматический перезапуск службы в случае сбоев (`Restart=always`).
5. Включает автозапуск при включении/перезагрузке ОС (`systemctl enable appeals.service`) и сразу запускает приложение.

### Управление службой:
```bash
# Проверить статус работы приложения:
sudo systemctl status appeals.service

# Посмотреть журнал и вывод логов в реальном времени:
sudo journalctl -u appeals.service -f

# Перезапустить приложение:
sudo systemctl restart appeals.service

# Остановить приложение:
sudo systemctl stop appeals.service

# Запустить приложение:
sudo systemctl start appeals.service
```

### Отключение и удаление автозапуска:
Если автозапуск больше не требуется, достаточно выполнить:
```bash
./uninstall_autostart.sh
```
